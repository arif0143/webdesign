Converting The HTML Website To WordPress — Elementor Free Version

Convert the attached HTML file(s) into a complete Elementor website on [YOURWEBSITE.COM]

- Business name: [YOUR BUSINESS]
- What I do: [YOUR SERVICES]
- Who I serve:[CUSTOMERS YOU SERVE]
- Main goal of the site: [GET LEADS / BOOK CALLS / SHOWCASE WORK]
- SEO keywords: [KEYWORD 1. KEYWORD 2, KEYWORD 3]

If the source is a template or someone else's site, ALL business info in it is placeholder. Swap in the details above and tell me anything the source contained that I didn't give you a replacement for. Never ship "123 Main Street", dead `#` social links, or lorem ipsum to a live site. If a nav item has no matching page in the build, tell me instead of pointing it somewhere arbitrary.
(Tip to self: plain HTML + an images folder converts several minutes faster than a single-file bundle.)

BUILD

- One Elementor page per HTML file; source filenames become titles and slugs. Home = front page (`show_on_front = page`, `page_on_front = its ID`). Every page: title hidden, `elementor_header_footer` template, relative links (`about.html` → `/about/`).
- Create the primary and footer menus from the source nav BEFORE anything references them — menu slugs must match what the nav widgets point at.
- Header and footer come from the repeated source markup, built as Solace Site Builder parts, displayed globally, editable under Solace → Site Builder.
- Images are in the media library — match by filename, use attachment IDs. Never re-upload, never hotlink.
- Every page and both parts ship with tablet and mobile overrides. Right-at-1440px-only isn't finished.

WIDGET SPLIT — don't blur it

- Regular pages: native free Elementor widgets and flexbox containers ONLY (heading, image, button, icon, icon-box, icon-list, divider, spacer, text-editor, social-icons, image-carousel, tabs, accordion, star-rating, counter, google_maps). No Solace widgets — one exception: `solaceform` for actual forms (Elementor's form widget is Pro-only), and tell me when you use it.
- Header/footer parts: `solace-extra-site-logo` and `solace-extra-nav-menu` do the work no free widget can; core widgets mix in freely. Text-lockup logos may use heading widgets instead of the logo widget.
- Shop/archive/single/404 parts (only if the build includes them): the `solace-extra-post-*` / `solace-extra-product-*` set. These part types need Solace Extra Pro; header/footer don't.
- Never: html widget, shortcode widget, inner sections, Elementor 4.x atomic elements (e-heading, e-image, e-button, e-paragraph, e-svg, e-divider, e-component), or any widget whose class contains `Promotion` (on free tier that's nav-menu, mega-menu, form, posts, loop-grid, theme-site-logo).

ORDER OF WORK

1. Check the site's Novamira skills for `elementor-build-facts` and check `wp-content/novamira-sandbox/` for a cached build. If a cache of this site exists, restore from it and skip conversion entirely. If the skill exists, trust its verified keys, breakpoints, kit IDs, and meta recipes — only query `get_controls` for widgets the skill doesn't cover. Only when neither exists, do full verification: confirm each planned widget is real (reject `Promotion` classes), which control keys are responsive (only responsive controls accept `_tablet`/`_mobile` suffixes — on anything else they're silently ignored), active breakpoints, kit global color/font IDs (only bind globals that exist — Solace starter kits ship dead references that silently fall back), and Site Builder meta keys. Never guess keys.
2. Read the source once, whole-site, before converting anything. If screenshots are provided or the source is a live URL, use the extractor + screenshot comparison from the html-to-elementor skill; for inline-styled HTML with no screenshots, read the markup directly and skip the extractor.
3. Build the header and footer parts FIRST and verify them on one page. A wrong header found after twelve converted pages wastes the run.
4. Convert page bodies using the html-to-elementor skill: flexbox containers only, run its validator on every template. Skill overrides: `_elementor_data` takes only the inner content array (not the template envelope); no html-widget fallback for unmappable CSS (use container/widget settings or append Customizer CSS via `wp_update_custom_css_post` in append mode — never overwrite); nav goes through `solace-extra-nav-menu`; swap external image URLs for library attachment IDs.
5. Write to the site server-side via execute-php with `wp_slash()` — update_post_meta strips backslashes and silently corrupts Elementor JSON otherwise. Use gzip+base64 staged payloads ONLY if a direct write fails or a single payload exceeds ~80KB; if staging, validate after decoding, max 3 payloads per call. Required meta per page: `_elementor_edit_mode = builder` (without it the page renders blank — confirmed live), `_elementor_template_type = wp-page`, `_elementor_version` = current, `_wp_page_template = elementor_header_footer`, `_elementor_page_settings = ['hide_title' => 'yes']`. Read the meta back and confirm it parses as JSON. Keep execute-php returns small — counts, booleans, short strings.
6. When every write is done, call `files_manager->clear_cache()` ONCE, then verify every live page. Not optional: Elementor caches rendered element HTML per post and serves stale content until this runs — LiteSpeed purges and deleting per-post cache meta do NOT fix this. Verifying before the clear reports phantom bugs.
7. Save/update the `elementor-build-facts` skill on the site with anything newly verified, and archive final payloads + a manifest to `wp-content/novamira-sandbox/` so the next run starts at step 3.

SOLACE SITE BUILDER FACTS

- Two header systems exist; an active Site Builder part completely replaces the Customizer header — the old header going quiet is expected. Header/footer parts work on free Solace Extra.
- Each part = published `solace-sitebuilder` post with: `_solace_template` = header|footer; `_solace_{header|footer}_status = '1'`; `_solace_{header|footer}_conditions = [['type'=>'include','value'=>'basic-global']]`; `_elementor_edit_mode = builder`; `_elementor_template_type = wp-post` (NOT header/footer — that's Pro's convention); `_wp_page_template = default`.
- Only one active part per type: Solace stacks every matching condition without checking earlier passes. Before activating, zero the status meta and delete stray conditions on EVERY other part, including trashed ones.
- The `solace-custom-header` marker div renders `display:none` with `post-id='0'` — that's normal, not a failure.

LAYOUT + RESPONSIVE RULES (breakpoints: mobile ≤767, tablet ≤1024)

- Widgets in a flex ROW default to width:100% and force-wrap: set `_element_width: "auto"` on menu/button widgets; logo uses `"initial"` + `_element_custom_width` in px (~175 desktop, 110–130 mobile) — `"auto"` ignores the px value.
- Column containers render no width CSS unless `content_width: "full"` AND a % width are both set.
- Every row gets an explicit `flex_gap` — unset inherits a theme default and wraps columns.
- Header structure (confirmed live): outer container column + z_index 99 → inner boxed row, space-between, align center, `flex_wrap: nowrap` (a wrapping row = two-line mobile header) → logo, nav, CTA.
- Nav widget: `dropdown: "tablet"` (never "none"), `toggle: "burger"`, `toggle_align: "right"`, `full_width: "yes"`, toggle_size_mobile ~22px, dropdown item padding for ~44px tap targets. Never `hide_mobile` on the nav — it removes the burger.
- Stacking: `flex_direction_mobile: "column"` on the row parent PLUS `width_mobile: 100%` on each column — width alone doesn't stack a nowrap row. 2×2 grids: `flex_wrap_mobile: "wrap"` + `width_mobile: 50%`. Tablet follows the source; default 3–4 col rows to 50%.
- Scale headings with `_mobile` font sizes, cut section `padding_mobile`. `hide_desktop`/`hide_mobile` to swap per-device content.
- Anchor sections: set both `css_id` and `_element_id` on the container.
- The Solace nav widget ships its own reset CSS — no bullet-stripping needed.
- Footer socials = core `social-icons` widget (`solace_social_share` is a post-sharing widget, not a links list).

VERIFY BEFORE REPORTING DONE

Cache already cleared in step 6. Strip `<style>` blocks before any markup check — Solace ships CSS mentioning `header--row` and `builder-item--logo` whether or not the old header renders, and raw text search will lie.

- Site Builder header renders once (not twice), Customizer header absent (no `id="header-grid"`) — on the front page, a subpage, and a post.
- Every page shows its converted content (blank body ≈ missing `_elementor_edit_mode`).
- Menu links resolve to real pages, no `.html` anywhere.
- Search live pages for the source's original company name, phone, address, and social URLs — any hit means a swap was missed. No "Go Pro" text, no images pointing at the source domain, no html/shortcode widgets.
- Burger exists, mobile and tablet media queries actually appear in the generated CSS — if absent, no responsive overrides were written.
- Load at 375px and look: no sideways scroll, burger opens/closes, nothing overlaps, buttons tappable.
- Note: fetching page HTML proves content renders, NOT that layout is right — the width rules above are applied from the start, and both nav layouts always ship in the DOM (CSS picks one), so menu markup in HTML doesn't prove mobile works.
- Report every approximation made against the source.

PROCESS — stable, reuse across projects

TOOLING (in this order)

2. Check Novamira memory before any discovery — reuse saved widget/schema calibration instead of re-deriving it.

For inline-styled HTML with no screenshots, read the markup directly and skip the extractor — it's complete and several minutes faster. Follow the skill's `schema.md` container rules either way; it documents render conditions server validation does not check.

SITE FACTS

- Elementor Pro is active — read the html-to-elementor skill's `pro-widgets.md` before using any Pro widget (the skill requires this when Pro is confirmed). Real widgets: nav-menu, mega-menu (Pro's Menu widget with nested item content — not a hover-hack), form, popups, Theme Builder, posts, loop-grid, per-element custom CSS (works on Pro; still prefer native controls so it stays editable in the UI). - Popups are `elementor_library` posts with template type `popup`; triggers and display conditions live in the popup's OWN page settings, not the button. The button opens it via the popup dynamic tag on its link control.

ORDER OF WORK

1. Read the source once, whole-site, before converting anything.
2. Build header, footer, and popup FIRST. Verify them live on one page before any page bodies. After writing the header, read it back and confirm every row child defines a width; a wrong header found after twelve pages wastes the run.
3. Convert page bodies. Write each fresh document in ONE set-content call if it fits the connector's payload cap (~10KB observed on Novamira Pro; confirm on first write); otherwise set-content the top-level skeleton, then add-element per section. Don't fight the cap — splitting up front beats retrying a hung call.
4. Keep every ability return small — counts, booleans, IDs. Large reads hit the connector's response-size ceiling and hang silently.
5. Batch final settings (display conditions, homepage, hide title) into a single step.
6. When ALL writes are done: clear Elementor's cache ONCE (`files_manager->clear_cache()`), then verify. Never verify before the clear — Elementor caches rendered element HTML per document and serves stale content until it runs; verifying early reports phantom bugs on markup that no longer exists.
7. Save calibration learnings to Novamira memory (widget structures, render-condition pairings, this site's quirks, v3/v4 surface) so the next build starts warm. If exporting .json templates, do it now.

BUILD RULES — layout

- Native widgets only. No HTML widgets, no shortcode widgets, no inner sections.
- Container widths: any container with a width value must ALSO set `content_width: "full"`, or Elementor silently drops the width CSS and every row collapses into stacked full-width blocks.
- Never emit a control whose render condition ("if" in the schema) isn't satisfied — the setting saves fine and renders nothing.
- Set `flex_gap` EXPLICITLY on every row container (0 for flush layouts) — unset inherits the theme default (~20px) and makes exact-100% columns wrap.
- Header structure: one row container, `flex_wrap: nowrap`, with a child CONTAINER per zone (logo / menu / buttons) — each zone container gets explicit width + `content_width: "full"` (containers render no width CSS otherwise). Widgets INSIDE the zones get `_element_width: "auto"` — a widget sitting bare in a flex row defaults to 100% and force-wraps. Don't mix the two rules up: width + content_width is for containers, `_element_width` is for widgets.
- Forms use the Pro form widget: real field IDs, at least one action-after-submit configured (email or redirect), and flag any placeholder recipient address to me — an unconfigured action fails silently on submit.

BUILD RULES — responsive (breakpoints: mobile ≤767, tablet ≤1024 unless check-setup says custom)

- Stacking: `flex_direction_mobile: "column"` on the row parent PLUS `width_mobile: 100%` on each column — width alone doesn't stack a nowrap row. 2×2 grids: `flex_wrap_mobile: "wrap"` + `width_mobile: 50%`. Tablet follows the source; default 3–4 col rows to 50%.
- Only responsive controls accept `_tablet`/`_mobile` suffixes — on anything else they're silently ignored. Trust the calibration for which is which.
- Nav-menu widget: set the mobile dropdown breakpoint (tablet, never "none"), hamburger toggle, full-width dropdown, ~44px tap targets on items. Never `hide_mobile` the nav — it removes the burger too. Mega menu needs its own mobile behavior checked, not assumed.
- Scale hero/section headings with `_mobile` font sizes; cut section `padding_mobile`. Logo ~175px desktop → 110–130px mobile.
- Popup: set mobile width/height overrides — a 900px popup on a 375px screen is unusable.

FINISH — verify before reporting done

- Verify LAYOUT, not just content: confirm `--width`, `--flex-direction`, and `--gap` variables exist in the generated post CSS files with expected values, and that mobile + tablet media queries actually appear — if they don't, no responsive overrides were written and phones get shrunk desktop.
- Confirm on the live URL: theme header/footer replaced (no double header), mega menu renders, popup opens from the button AND its form submits without error, anchors work, every page shows its converted content.
- Search live pages for the source's original company name, phone, address, and social URLs — any hit means a swap was missed. No images pointing at the source domain.
- Load at 375px and look: no sideways scroll, burger opens/closes, mega menu usable, popup fits, nothing overlapping.
- Report: live URL, edit URLs per template, and everything approximated or needing my input (video URLs, form actions, missing sections).
